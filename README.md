# ccmcp

Self-hosted knowledge base for AI coding assistants. Indexes your local code and documentation into a hybrid vector search engine and exposes it to Claude Code and Cursor via the Model Context Protocol (MCP).

When you ask Claude Code a question, it calls `qdrant_find` to retrieve the most relevant passages from everything you've indexed — your private repos, internal docs, architecture notes, runbooks. Results stay local; nothing is sent to a third-party embedding or retrieval service.

---

## How it works

```
Your files / docs / web pages
        │
        ▼
  Structural chunker          split at headings, functions, paragraphs
        │
        ▼
  fastembed (ONNX)            dense: BAAI/bge-small-en-v1.5 (384-dim)
                              sparse: Qdrant/bm25
        │
        ▼
  Qdrant                      hybrid dense + sparse search (RRF fusion)
        │
        ▼
  MCP server                  qdrant_find · qdrant_store
        │
        ├── stdio  →  Claude Code CLI (subprocess, auto-discovered)
        └── SSE    →  Cursor IDE  http://localhost:7700/sse
```

Embeddings run entirely on-device via ONNX. On Apple Silicon the Neural Engine is used automatically; on Linux/WSL2 the CPU ONNX runtime is used (AVX2 if available).

## Quick start

### Option A — Docker (recommended)

**Prerequisites:** Docker with Compose.

```bash
# Clone and start
git clone https://github.com/your-user/ccmcp
cd ccmcp

# Point REPOS_PATH at the directory that contains your projects
REPOS_PATH=~/code docker compose up -d
```

That's it. ccmcp will:
1. Start Qdrant (exposed on `localhost:6333` for inspection)
2. Generate the rotation matrix and create collections (`ccmcp init`)
3. Index everything under `~/code` on first startup
4. Watch for changes and re-index modified files in the background
5. Serve the MCP SSE endpoint at `http://localhost:7700/sse`

**Connect Cursor:** Settings → MCP → add server URL `http://localhost:7700/sse`.

**Connect Claude Code:** Add to `~/.claude.json`:
```json
{
  "mcpServers": {
    "ccmcp": {
      "type": "sse",
      "url": "http://localhost:7700/sse"
    }
  }
}
```

> **Enable workspace auto-scoping** (recommended): edit `docker-compose.yml` and
> uncomment the `CCMCP_HOST_MOUNT` / `CCMCP_CONTAINER_MOUNT` lines under the
> `ccmcp` service. Without them, Claude Code's workspace root won't match any
> indexed project and search silently falls back to the full corpus.
> See [Workspace scoping under Docker](#workspace-scoping-under-docker) below.

#### Pin to a release

The compose file ships with `image: ghcr.io/andrey-stepantsov/ccmcp:latest`,
which tracks `main` and moves on every push. For reproducible installs, pin to
a release:

```yaml
# docker-compose.yml — ccmcp service
image: ghcr.io/andrey-stepantsov/ccmcp:0.2.1   # immutable release pin
# image: ghcr.io/andrey-stepantsov/ccmcp:0.2   # rolling 0.2.x (gets 0.2.x patches)
```

Published tags per release: `:X.Y.Z` (immutable), `:X.Y` (rolling minor),
`:sha-<commit>` (per-commit pin), plus `:latest` and `:main` for tracking
`main`. List available tags at
[ghcr.io/andrey-stepantsov/ccmcp](https://github.com/andrey-stepantsov/ccmcp/pkgs/container/ccmcp).

### Option B — Local install (no Docker)

**Prerequisites:** Python 3.12+, [Qdrant](https://qdrant.tech/documentation/quick-start/).

```bash
# 1. Start Qdrant (pick one)
qdrant                                      # if installed natively
docker run -p 6333:6333 qdrant/qdrant       # or via Docker

# 2. Install ccmcp
pip install uv
git clone https://github.com/your-user/ccmcp
cd ccmcp
uv pip install -e .

# 3. Configure
cp config.example.yaml config.yaml
# Edit config.yaml — add your paths to sources.filesystem.paths

# 4. First-time init (generates rotation matrix, creates Qdrant collections)
ccmcp init

# 5. Index your files
ccmcp scan

# 6. Start the MCP SSE server
ccmcp serve
```

## Configuration

Copy `config.example.yaml` to `config.yaml` and edit:

```yaml
qdrant:
  url: "http://localhost:6333"    # Qdrant URL
  collection: "techdocs"          # collection name
  # api_key: ""                   # Qdrant Cloud only

embedding:
  dense_model: "BAAI/bge-small-en-v1.5"
  sparse_model: "Qdrant/bm25"
  rotation_matrix: "~/ccmcp/rotation_matrix.npy"  # generated by: ccmcp init

sources:
  filesystem:
    enabled: true
    paths:
      - ~/code/my-project                  # plain path, name defaults to directory name
      - path: ~/code/api-server            # with scope metadata
        name: api-server
        tags: [go, backend]
        include: [shared-lib]              # pull in shared-lib chunks automatically
    extensions: [".md", ".rst", ".txt", ".py", ".go", ".ts"]
    ignore: ["node_modules", ".git", "__pycache__", ".venv"]
    watch: true
    poll_interval: 30             # seconds between filesystem polls

  web:
    enabled: false
    urls:
      - "https://docs.example.com/api"
    sitemaps:
      - "https://docs.example.com/sitemap.xml"
    rate_limit_ms: 500

  google_drive:
    enabled: false
    credentials_file: "/path/to/service-account.json"
    folders:
      - id: "1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgVE2upms"
        name: "Internal Docs"
    poll_interval_min: 15

mcp:
  host: "127.0.0.1"
  port: 7700
  result_limit: 10                # max results returned by qdrant_find

state:
  db_path: "~/.local/share/ccmcp/state.db"
  artifact_ttl_days: 30           # auto-expire agent-written artifacts
```

**Environment variable overrides:**

| Variable | Description |
|---|---|
| `CCMCP_CONFIG` | Config file path (default: `config.yaml` in working directory) |
| `CCMCP_SOURCE_PATH` | Overrides `sources.filesystem.paths` with a single path. Used by the Docker entrypoint; project name is derived from the path basename |
| `CCMCP_HOST_MOUNT` | Host-side prefix to remap before matching MCP workspace roots (paired with `CCMCP_CONTAINER_MOUNT`). See [Workspace scoping under Docker](#workspace-scoping-under-docker) |
| `CCMCP_CONTAINER_MOUNT` | Container-side prefix that `CCMCP_HOST_MOUNT` is remapped to |
| `QDRANT_URL` | Qdrant endpoint |
| `QDRANT_API_KEY` | Qdrant Cloud API key |
| `QDRANT_COLLECTION` | Override the configured Qdrant collection name |
| `FASTEMBED_CACHE_PATH` | ONNX model cache directory (`/models` in Docker; defaults to `/tmp/fastembed_cache`). Set to a persistent path to avoid re-downloading on container restart |
| `ANTHROPIC_API_KEY` | For future Phase 2 proposition extraction (not yet active) |

## Using the CLI with Docker

The Docker container runs `ccmcp run` as its entrypoint. Install the wrapper script once for a clean CLI experience:

```bash
sudo curl -fsSL https://raw.githubusercontent.com/andrey-stepantsov/ccmcp/main/bin/ccmcp \
  -o /usr/local/bin/ccmcp && sudo chmod +x /usr/local/bin/ccmcp

# Add to ~/.bashrc or ~/.zshrc
export CCMCP_DIR=~/code/ccmcp   # directory containing docker-compose.yml
```

Then all commands work without the `docker compose exec ccmcp` prefix:

```bash
ccmcp status
ccmcp doctor
ccmcp ingest /repos/my-project/README.md
ccmcp scan
ccmcp reset
```

Without the wrapper, prefix each command with `docker compose exec ccmcp`:
```bash
docker compose exec ccmcp ccmcp status
```

Inside the container: repos at `/repos/`, rotation matrix and state DB at `/data/`, Qdrant at `http://qdrant:6333` — all wired automatically. No config file needed for basic use.

## CLI reference

```
ccmcp init
```
Creates Qdrant collections (idempotent) and generates `rotation_matrix.npy`. Run once before first use. Refuses to overwrite an existing rotation matrix — regenerating it would invalidate all indexed vectors.

```
ccmcp scan
```
One-shot ingestion of all configured sources. Skips unchanged files (SHA-256 dedup). Safe to run repeatedly.

```
ccmcp watch
```
Runs a full scan, then watches for file changes continuously (polling observer, hourly full rescan).

```
ccmcp serve [--host HOST] [--port PORT]
```
Starts the MCP SSE server. Prometheus metrics are available at `/metrics` on the same port.

```
ccmcp run [--host HOST] [--port PORT]
```
Starts both the ingestion controller (watch mode) and the MCP SSE server in a single process. This is what the Docker entrypoint uses.

```
ccmcp ingest <path-or-url>
```
Ingest a single file or URL immediately, without a full scan.

```
ccmcp status
```
Shows collection stats (points count, vector count, segment count), artifact collection size, and a per-type breakdown of indexed sources.

```
ccmcp doctor
```
Runs the built-in end-to-end validation suite against a temporary Qdrant collection: ingestion, hybrid retrieval quality across 8 scenarios, versioned document swap, and artifact round-trip. Exits 0 on full pass, 1 on any failure.

```
ccmcp reset
```
Drops all Qdrant collections and deletes the state database. Prompts `Type RESET to confirm`. Does not delete `rotation_matrix.npy`.

```
ccmcp save-config [-o FILE]
```
Export the current resolved config (file + env vars + defaults) to YAML. Defaults to stdout. Use with load-config to restore on a new deployment.

```
ccmcp load-config <file>
```
Validate and install a config file to the active config path (CCMCP_CONFIG env var). After loading, run `ccmcp init` and `ccmcp scan` to rebuild the dataset.

```
ccmcp save-snapshot [-o FILE]
```
Archive the rotation matrix and state DB to a .tar.gz file (default: ccmcp-snapshot.tar.gz). Enables fast recovery — restoring a snapshot means `ccmcp scan` skips unchanged files.

```
ccmcp load-snapshot <archive>
```
Restore rotation matrix and state DB from a snapshot archive. After loading, run `ccmcp init` then `ccmcp scan`.

## Backup and restore

### Config backup

```bash
# Save current config to a file
ccmcp save-config -o config-backup.yaml

# Restore on a new deployment
ccmcp load-config config-backup.yaml
ccmcp init
ccmcp scan
```

### Full snapshot (fast recovery)

A snapshot archives the rotation matrix and state DB. After restoring, `ccmcp scan` skips unchanged files — much faster than a clean re-index.

```bash
# Save
ccmcp save-snapshot -o /data/snapshot.tar.gz

# Restore (on new deployment)
ccmcp load-snapshot /data/snapshot.tar.gz
ccmcp init
ccmcp scan
```

> **Note:** The Docker named volume (`ccmcp-data`) survives `docker compose down`. Only `docker compose down -v` removes it. Snapshots are for cross-machine migration or deliberate disaster recovery.

### Rotation matrix

The rotation matrix (`rotation_matrix.npy`) is generated once by `ccmcp init` and must never be regenerated — it would invalidate all vectors in the index. It is included in every snapshot. Back it up independently if you are not using snapshots.

## MCP tools

The server exposes three tools to connected AI assistants:

**`qdrant_find(query, limit=10, scope=None)`**
Search the knowledge base. Returns up to `limit` passages ranked by hybrid dense+sparse relevance.

The `scope` parameter controls which projects are searched:

| `scope` value | Behaviour |
|---|---|
| omitted / `None` | Automatic — scoped to the active workspace root via MCP roots (resolved against configured paths) |
| `["project-a", "shared-lib"]` | Explicit — search only chunks whose `project_name` or `tags` match any listed value |
| `["*"]` | Unfiltered — search the full corpus regardless of active project |

**`qdrant_list_scopes()`**
Returns all project scopes currently in the knowledge base — name, tags, and root path for every project indexed with scope metadata declared in config. Agents call this to discover what scope values are available before passing them to `qdrant_find`.

Example output:
```
3 project scope(s) in the knowledge base:

• api-server
  tags: api-server, backend, go
  root: /home/user/code/api-server

• shared-proto
  tags: protobuf, shared-proto
  root: /home/user/code/shared-proto

• web-frontend
  tags: react, typescript, web-frontend
  root: /home/user/code/web-frontend

Use names or tags in qdrant_find: scope=["my-project", "shared-lib"]
To search everything: scope=["*"]
```

**`qdrant_store(text, title="", session_id="")`**
Write a note or artifact into the knowledge base. Useful for Claude to save decisions, summaries, or work-in-progress context. Artifacts expire after `state.artifact_ttl_days` days (default 30).

## Project context scoping

When you index multiple projects, `qdrant_find` by default searches the entire corpus. Scope metadata declared in `config.yaml` enables two things: it labels indexed chunks with a project identity, and it declares which other projects' content the agent should include when working in a given project.

### Declaring scope in config

```yaml
sources:
  filesystem:
    paths:
      - path: ~/code/api-server
        name: api-server
        tags: [go, backend]
        include: [shared-proto]    # pull in shared-proto chunks automatically

      - path: ~/code/web-frontend
        name: web-frontend
        tags: [typescript, react]

      - path: ~/code/shared-proto
        name: shared-proto
        tags: [shared-proto, protobuf]
```

Every chunk indexed from a path with metadata is stamped with `name`, `tags`, and `source_root` in its Qdrant payload. Plain string paths (no metadata) are indexed without scope labels.

### Automatic scoping (workspace-driven)

When an AI assistant opens a project (Claude Code sends its workspace root via the MCP protocol), `qdrant_find` automatically restricts results to that project's chunks, plus any additional projects declared in `include`.

This requires no action from the agent — it happens transparently based on which directory is open. ccmcp uses **longest-ancestor-prefix** matching, so opening a subdirectory of an indexed project still resolves to that project.

### Workspace scoping under Docker

When ccmcp runs inside Docker, the indexed paths are container-side (e.g. `/repos/my-project`). The MCP client (Claude Code, Cursor) runs on the host and sends a host-side workspace root (e.g. `/home/alice/code/my-project`). Without a translation step, the host root won't match any configured path and auto-scoping silently falls back to full-corpus search.

Set the following two env vars on the `ccmcp` container so workspace roots arriving from the host are remapped before matching:

```yaml
# docker-compose.yml — ccmcp service environment
CCMCP_HOST_MOUNT: /home/alice/code          # what the agent sees
CCMCP_CONTAINER_MOUNT: /repos               # what ccmcp indexes
```

With these set, a Claude Code workspace root of `file:///home/alice/code/my-project` is remapped to `/repos/my-project` before the longest-prefix match, and `qdrant_find` correctly scopes to that project's chunks.

The shipped `docker-compose.yml` has these lines commented out — uncomment them and set the host path to whatever you passed as `REPOS_PATH`:

```yaml
environment:
  CCMCP_HOST_MOUNT: ${REPOS_PATH:-$HOME/code}
  CCMCP_CONTAINER_MOUNT: /repos
```

> **Confirming it's wired correctly:** if no MCP root matches any configured
> path, ccmcp logs a one-line warning (`no configured source matches MCP roots …`)
> before falling back to unscoped search. Tail the container logs while the
> agent runs its first query to verify auto-scoping kicked in.

> **Limitation:** only a single host→container pair is supported per
> container. Multi-mount setups need to run separate ccmcp containers per
> mount, or fall back to explicit `scope=[…]` in the agent's `qdrant_find`
> calls.

### Agent-controlled scoping (explicit)

The agent can also control scope directly:

```
# Discover what projects are indexed
qdrant_list_scopes()

# Search a specific cross-project combination
qdrant_find("authentication middleware", scope=["api-server", "shared-lib"])

# Search everything — bypass all filtering
qdrant_find("where is X defined", scope=["*"])
```

**Fallback:** If the active workspace root does not match any configured path, search is unfiltered (full corpus).

## How sources are indexed

### Filesystem

Files are discovered by walking configured paths, filtered by extension and ignore patterns. Changed files are detected by SHA-256 content hash; unchanged files are skipped. New content is upserted into Qdrant **before** old vectors are deleted, so the collection is never incomplete during updates.

Supported by default: `.md .rst .txt .py .go .rs .js .ts .yaml .yml .c .cpp .cc .cxx .h .hpp .hh`

> `.json` is **not** in the defaults — lockfiles and generated schemas inflate
> the index with low-value chunks. Add it to `sources.filesystem.extensions` in
> `config.yaml` if you index hand-written JSON.

A per-path `.gitignore` is honoured by default (cascading with parent `.gitignore`
files, supporting `**`, anchored patterns, and within-file `!` negation). Disable
this with `sources.filesystem.respect_gitignore: false` if you want every file
matching `extensions` indexed regardless.

### Web URLs and sitemaps

URLs are fetched with `httpx`. ETag/`Last-Modified` headers are used to skip unchanged pages (304 Not Modified). HTML is converted to plain text via `readability-lxml`. Sitemaps are expanded automatically.

### Google Drive

Requires a service account with `drive.readonly` scope. Supported MIME types: Google Docs (exported as plain text), `.txt`, `.md`. Change detection via Drive `modifiedTime` and `version` fields.

## Chunking

Documents are split into 50–512 token chunks at natural boundaries:

| File type | Split boundary |
|---|---|
| Markdown (`.md`) | Headings (H1–H4), then blank-line paragraphs |
| reStructuredText (`.rst`) | Section title underlines, then paragraphs |
| Python / Go / Rust | Top-level `def`, `class`, `func`, `fn`, `impl` |
| JavaScript / TypeScript | Top-level `function`, `class`, `const`/`let`/`var` with arrow functions |
| C / C++ (`.c .cpp .cc .cxx .h .hpp .hh`) | Top-level function definitions / declarations |
| Plain text / YAML | Blank-line paragraph boundaries |

Each chunk prefixes the nearest heading so retrieval context is self-contained. Chunks smaller than 50 tokens are merged with the next chunk.

## Validation

```bash
ccmcp doctor
```

Runs four phases against a fresh, isolated Qdrant collection that is dropped on exit:

1. **Fixture ingestion** — writes 4 embedded documents (Markdown, Python, RST, plain text)
2. **Retrieval quality** — 8 scenarios testing exact keyword and semantic retrieval
3. **Version swap** — ingests a document, updates it, verifies old content is gone
4. **Artifact round-trip** — stores an artifact and runs TTL cleanup

Exits 0 if all scenarios pass, 1 otherwise. Safe to run in CI alongside unit tests.

## Architecture notes

**Hybrid search:** Dense vectors (cosine similarity) cover semantic meaning. Sparse BM25 vectors cover exact vocabulary — critical for technical terms like hostnames, CLI flags, and model names. Reciprocal Rank Fusion merges both ranked lists.

**Random orthogonal rotation:** A random QR-decomposed rotation matrix is applied to all dense vectors before upsert. This redistributes variance uniformly across dimensions, improving INT8 scalar quantisation effectiveness without changing inner product structure. The matrix is generated once by `ccmcp init` and must never be regenerated after the first ingestion (it would invalidate all stored vectors).

**Versioned atomic swap:** When a file changes, new chunks are upserted first, verified, then old chunks (identified by `doc_id + old_version`) are deleted. The collection is never left in a partially-updated state.

**State database:** A SQLite database at `~/.local/share/ccmcp/state.db` tracks every indexed source URI with its content hash, version, and last-seen timestamp. Orphan cleanup runs after every full scan to remove vectors for sources that no longer exist.

## Troubleshooting

**"No results found" for queries I know are in the index**
- Run `ccmcp status` to confirm the collection has points.
- Run `ccmcp doctor` to check retrieval quality end-to-end.
- Verify the active workspace root matches a configured path in `sources.filesystem.paths`.

**Qdrant connection refused**
- Check Qdrant is running: `curl http://localhost:6333/healthz`
- In Docker, ensure the `qdrant` service is healthy before `ccmcp` starts (the entrypoint polls until ready).
- The shipped `docker-compose.yml` publishes Qdrant on `localhost:6333` so the host can inspect it (`/healthz`, `/collections`, `/metrics`). If you'd rather keep it network-internal, delete the `qdrant.ports` stanza; the `ccmcp` container reaches Qdrant via the internal `http://qdrant:6333` regardless.

**`rotation_matrix.npy` already exists error**
- This is intentional. Regenerating the matrix invalidates all vectors. Run `ccmcp reset` first if you want to start over from scratch.

**inotify events not firing on WSL2**
- Paths under `/mnt/c/` and `/mnt/d/` use a 9P filesystem layer that does not propagate inotify events. ccmcp uses a polling observer automatically for these paths. Reduce `poll_interval` in config if you need faster detection, or keep source repos in `~/` inside WSL2.

**Embedding is slow**
- First call loads ONNX models from disk (~60 MB for the dense model). Subsequent calls are fast.
- On Linux without AVX2, embedding throughput is lower; consider indexing on a machine with AVX2 support.
